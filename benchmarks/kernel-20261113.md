# Full 查询与 SHACL 优化实测：2026-11-13

本轮在 **API v1 请求、结果及既有 SHACL 目标语义保持不变**的前提下，统一单次与常驻实例的快照实现，补齐 Full 查询扫描索引，并优化 SHACL 图导航。10 万条显式事实上，同一文件 API 的全图计数从 **4.138 s 降至 95.82 ms**，推导事实分组计数从 **3.804 s 降至 105.33 ms**，显式类目标 SHACL 从 **26.147 s 降至 1.237 s**。

## 改动及其作用

1. **共用 FullSnapshot。** 单次 `api` 请求持有短生命周期实例，`api-session` 保留实例。实例核验后只复制一次匿名只读 SQLite 文件；worker 继承只读 FD，不按原路径重开。单次默认响应字段保持原样，常驻成功响应增加复用指标。
2. **增加覆盖 SPO 索引。** 查询读取器按 `(s,p,o[,g])` 每 256 行做 keyset 分页，原 facts 索引只有 G/S/P/O 主键、POS 和 OSP。新增 `facts_spo(s,p,o,g,explicit)` 匹配这个扫描顺序，保留原 SQL、默认图 union 去重、具名图、视图与预算规则。
3. **SHACL 图导航使用索引。** SPO 范围读取、按需 POS 引用索引及反向子类/类型遍历替代重复全图扫描；简单谓词路径直接读取 SPO；复杂路径/SPARQL 的查询数据集按需创建；已明确传入 focus 的原生校验不重复建 target 索引。
4. **保留目标语义与执行边界。** `rdfs:Class` 注解仍不自动创建隐式 target，显式 `sh:targetClass` 的传递子类语义保留。匿名快照按已核验字节预留 scratch，复制不能超过预留大小；源文件增长按无效数据集拒绝。worker 仍逐请求隔离、先终止并 wait 再返回终态。

[常驻协议及生命周期](../docs/session-v1.md)说明了挂载、取消、切换和平台边界。[Full 合同](../docs/full.md#shacl)继续定义本轮没有扩展的语义范围。

## 文件 API：相同调用边界的前后比较

以下时间包含进程启动、每次完整核验与快照复制、求值和结果读取。所有行使用相同 transport，可直接做本轮描述性比较。

### 100,000 条显式事实

| 工作负载 | 优化前 | 优化后 | 前 / 后 |
|---|---:|---:|---:|
| Full 全部显式事实计数 | 4,137.54 ms | 95.82 ms | 43.18× |
| 推导事实按谓词分组计数 | 3,804.13 ms | 105.33 ms | 36.12× |
| 区域聚合 | 910.57 ms | 491.93 ms | 1.85× |
| 订单—客户—区域连接 | 159.41 ms | 107.45 ms | 1.48× |
| Full 点查 | 44.80 ms | 44.49 ms | 1.01× |
| closure 连接 | 45.36 ms | 54.91 ms | 0.83× |
| SHACL 显式 targetClass，全部订单 | 26,147.26 ms | 1,237.45 ms | 21.13× |
| SHACL targetSubjectsOf，全部订单 | 2,130.14 ms | 1,450.58 ms | 1.47× |
| SHACL Core minCount 负控制 | 1,260.73 ms | 817.84 ms | 1.54× |

三个主要改进的正式样本区间分别为：COUNT **4.065–4.306 s → 95.67–105.62 ms**；推导谓词计数 **3.795–3.837 s → 96.08–106.08 ms**；显式类目标 SHACL **25.908–28.623 s → 1.137–1.252 s**。结果均精确核对，SHACL 检查同样的 9,999 个目标并包含负控制，收益没有来自少算目标或跳过约束。

文件 API 的点查基本持平，closure 连接由 **45.36 ms 增至 54.91 ms（+21.05%）**，应保留为回退记录。更大的数据库增加了文件入口重复核验/复制的数据量，但现有 API 没有独立查询核心计时，本实验不能把这 9.55 ms 差值完整归因于复制或查询计划。

SHACL 类目标的 API 报告峰值 RSS 中位数从 **281.41 MiB 降至 167.43 MiB**。这是监督进程/worker 的预算计量值，包含采样和共享页影响，不是 PSS，也不能直接推算生产可支持并发数。

## 编译、物化和空间代价

100,000 条显式事实的独立构建中位数如下；每次都生成新的完整产物。

| 工作负载 | 优化前 | 优化后 | 前 / 后 |
|---|---:|---:|---:|
| pack 编译 | 203.18 ms | 204.33 ms | 0.99× |
| Full 编译 | 759.51 ms | 816.35 ms | 0.93× |
| Full 规则物化 | 1,051.64 ms | 1,187.22 ms | 0.89× |

Full 编译中位数增加 **7.48%**，物化增加 **12.89%**。这是本轮观测代价，不能因为读性能更好而省略。相同新版在 session 报告中的编译/物化另三轮也保留了主机波动，未取其中较快值替换上表。

规则 profile 为 `rdfs-supported-v1` 加 3 条显式正向规则；两版均完成 **8 轮不动点、136 次规则求值**，10 万条输入均得到 **86,240 条推导事实、186,240 条合计事实**。本轮没有声称改进规则物化算法。

| 100K 产物逻辑字节 | 优化前 | 优化后 | 增幅 |
|---|---:|---:|---:|
| compiled facts.sqlite | 11,988,992 | 13,369,344 | +11.51% |
| compiled 整个产物目录 | 24,017,545 | 25,397,897 | +5.75% |
| reasoned facts.sqlite | 15,650,816 | 18,309,120 | +16.99% |
| reasoned 整个产物目录 | 27,679,520 | 30,337,824 | +9.60% |

数据库增大是新增索引的真实成本。整个产物还保留冻结输入、规则和 manifest，因此与仅数据库的增幅不同。单次入口的 scratch 包含数据库预留；session 每个实例只预留一次数据库，请求 scratch 单列，不能把请求中排除的挂载空间视为零磁盘消耗。

## 常驻实例与冷启动

常驻模式的请求计时从写入一行 v1 JSON 到读完响应行；挂载在请求计时之外。**它与文件 API 的时间边界不同，比较器会拒绝将二者当成同口径回归对照。** 下表用于展示部署选择，不给“同等条件加速倍数”。

| 100K 工作负载 | 新版文件 API，中位数 | 新版常驻请求，中位数 |
|---|---:|---:|
| Full 点查 | 44.49 ms | 12.30 ms |
| Full 全部显式事实计数 | 95.82 ms | 63.75 ms |
| 推导事实按谓词分组计数 | 105.33 ms | 63.72 ms |
| SHACL 显式 targetClass，全部订单 | 1237.45 ms | 1336.45 ms |

96 次 Full 常驻读取（含预热）均确认 `snapshot_reused=true`、`snapshot_bytes_copied=0`；仍执行了独立 worker 内的查询/校验，没有查询结果缓存。

| 显式事实 | 挂载产物 | 新进程到 READY | READY 内部挂载计时 | 本次复制字节 |
|---:|---|---:|---:|---:|
| 10,000 | compiled | 5.86 ms | 3.75 ms | 1,409,024 |
| 10,000 | reasoned | 6.76 ms | 4.23 ms | 1,867,776 |
| 100,000 | compiled | 39.61 ms | 35.99 ms | 13,369,344 |
| 100,000 | reasoned | 56.11 ms | 54.01 ms | 18,309,120 |

每份产物只观测一次挂载；以上是**新实例启动实测**，并非冷盘时间分布、稳定上限或生产 SLO。数据生成、编译和核验已可能预热 OS 文件缓存。更大的真实 Bundle、慢盘及更多冻结来源会改变启动成本。

常驻内核保留已核验元数据和只读数据库文件；OS 可以复用文件页。worker、SQLite 连接/page cache、查询计划、SHACL 图仍是每请求创建。READY 不代表这些 worker 内部状态已经常驻。

部署时，应用适配器先挂载新 Bundle、执行代表性读请求，再切换该 Pod 接收新请求的实例；旧实例等待在途请求完成后释放。业务 API v1 无需改字段，但逐调用启动并退出进程的适配器需要保留 `api-session` 才能获得跨请求快照复用。新增 SPO 索引需要用新版重新 compile；旧兼容产物不会原地改写，只 materialize 旧 compiled 也不会补建索引。新产物使用新的摘要前置条件。
